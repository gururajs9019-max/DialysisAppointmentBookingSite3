## 3. Automatically Update Dialysis Status Based on Scheduled Time

Currently, dialysis sessions may remain in the Waiting status even when their scheduled time has arrived.

Implement automatic status updates based on the actual current time.

### Required statuses

Use the application's existing status system where possible. The relevant statuses should behave as follows:

- **Waiting:** The dialysis session is scheduled but has not reached its start time.
- **Running:** The scheduled start time has arrived, and the session is eligible to begin.
- **Completed:** The dialysis session has been marked as completed by an authorized user.
- **Cancelled:** The appointment has been cancelled.
- **Missed:** The appointment was missed according to the application's existing workflow or an authorized user's action.

Do not automatically mark a session Completed or Missed solely because time has passed.

### Automatic transition from Waiting to Running

When the current date and time reaches the scheduled start time of a dialysis session, automatically update its status from Waiting to Running, provided that:

- The session is scheduled for the current date.
- The session has not been cancelled, completed, or marked as missed.
- The session has not already started.
- The session is still eligible to run under the existing scheduling rules.

For example:

If a patient's slot is scheduled for 8:00 AM–12:00 PM, the status should automatically change from Waiting to Running at 8:00 AM local time, if the session is eligible to start.

Apply the same rule to the 12:00 PM and 4:00 PM slots.

### Technical requirements

- Use the correct hospital/local timezone configured by the application. Do not rely on an inconsistent mix of browser time, UTC, and server time.
- Implement status updates using a reliable backend mechanism, such as a scheduled task, background job, or server-side status evaluation.
- If the application does not support background jobs, implement the safest compatible alternative and ensure the status is refreshed when the relevant pages load or update.
- Do not rely exclusively on a frontend timer, because it may stop when the browser is closed.
- Make the update idempotent so the same session is not repeatedly transitioned or processed.
- Refresh the status in Today's Dialysis and Live Schedule without requiring the administrator to manually change it.
- Ensure cancelled or completed sessions never revert to Running.
- Handle rescheduled appointments using their updated date and start time.
- Do not automatically start a dialysis machine or operate physical medical equipment. This is a scheduling-status update only.

### Important clarification

A scheduled start time does not necessarily confirm that the patient has physically started dialysis. If the existing system tracks actual treatment initiation, preserve that distinction and use the appropriate status semantics. Do not fabricate clinical treatment events.
